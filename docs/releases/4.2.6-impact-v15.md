Angband with the Borg (the built-in automatic player) compiled in and 137 verified C Borg fixes, on official Angband master of 2026-11-19 ([milestone 15](https://github.com/diegoami/better-borg-c/issues/547)). Download one of the assets below. You don't need to clone this repository, which mostly holds tooling and evidence.

**Base:** angband/angband [`574b618c3`](https://github.com/angband/angband/commit/574b618c3bfec595f3503a58f8e488b1c4ae3a46), master of 2026-11-19, which is Angband 4.2.6 plus later development work. This is not the 4.2.6 release tag, and the patch does not apply there. Earlier releases (v9.1) were built on `e473720`.

## What's in it

- **137 carried fixes**, as reviewed up to [milestone 14](https://github.com/diegoami/better-borg-c/issues/542). Each fix links its issue in `BETTER-BORG-UNITS.md` (source asset) or `provenance/` (patch asset).
- **Five earlier fixes now come from official Angband itself:** the safer emergency swap, the knockout reaction gate, the healing-chance signs, the teleport landing check, and slays kept across equipment slots. The last three arrived with this base ([PR #546](https://github.com/diegoami/better-borg-c/pull/546)). Their local patches are retired; on their test cases the upstream versions behave exactly as the local fixes did.
- **Upstream engine changes since v14's base:** more consistent trap display, SDL2 control values, Windows open-dialog and compiler-warning fixes.
- The crash correction to patch 0099 ([PR #398](https://github.com/diegoami/better-borg-c/pull/398)) and the munchkin start by class ([PR #302](https://github.com/diegoami/better-borg-c/pull/302)), on by default: Warriors, Druids and Rangers stair-scum to DL6 first. Turn it off with `borg_munchkin_by_class = FALSE` in `borg.txt`.
- **Two local improvements**, this project's own changes rather than upstream bug fixes:
  - I-001: do not retreat from a lone adjacent monster that one blow would kill ([PR #394](https://github.com/diegoami/better-borg-c/pull/394)).
  - I-002: heal while fleeing at survivable danger ([PR #414](https://github.com/diegoami/better-borg-c/pull/414)).

Each asset contains the full instructions in `INSTALL.md` (`BETTER-BORG-INSTALL.md` in the source tree). The same guide is [docs/RELEASE-INSTALL.md](https://github.com/diegoami/better-borg-c/blob/4.2.6-impact-v15/docs/RELEASE-INSTALL.md).

**Using the Borg:** start a character, press **Ctrl-Z**, press **Space** twice, answer **y**, then press **z**. Any key stops it, and Ctrl-X saves and quits. Use disposable characters.

## Verification of this release

- **Native gate on the release tree:** 966/966 unit tests and 5/5 front-end tests, locally and in hosted CI.
- **Milestone review:** [#547](https://github.com/diegoami/better-borg-c/issues/547), independent agent review from a fresh clone, approve with corrections. The corrections are tooling-only and come with the next release, notably an `apply.sh` that refuses a checkout without the base; this release's `apply.sh` only warns, so check out `574b618c3` as described.
- **Prior-fixture regression matrix:** 121 groups / 371 cases, all passing. Every log and outcome row is byte-identical to milestone 14's.
- **Patch asset:** applied to a fresh `574b618c3` checkout, it reproduces `src/`, `lib/` and `CMakeLists.txt` of the release commit exactly. On the 4.2.6 tag it refuses and changes nothing.
- **Source asset:** builds on its own and passes 966/966 and 5/5.
- **Linux binary:** the binary attached here is built by the `release` workflow, which checks that it starts under Xvfb. Before tagging, binaries built from the same tree in the build container were played under Xvfb with random characters (a Half-Orc Ranger, a Dunadan Blackguard and a Half-Troll Mage): the Borg learned spells, bought gear, cast and moved on its own, and Ctrl-X saved the game. `play.sh` keeps all user files inside the package directory.
- **Reproducible:** the source and patch tarballs come out byte-identical when rebuilt with `tools/make-release.py --ref '4.2.6-impact-v15^{commit}'`: patch `8da107b0…7286`, source `c826916d…43b4`, the values posted on #547. The full checksums are under *Build facts*.
- **Not measured:** the per-mode effect on play (unrestricted, munchkin/Lunal, normal).
